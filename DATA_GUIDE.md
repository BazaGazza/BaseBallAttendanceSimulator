# Ballpark Factors & Attendance Dynamics — Dataset & Codebook Guide

This document serves as the official data dictionary and reference guide for the cleaned CSV files generated by `code time.py`. It details what each row (entity record) represents, describes all attributes/columns, explains Retrosheet encoding conventions, and maps out how the tables relate in a relational database.

---

## 1. Overview of Cleaned Entities

| CSV File | Entity | What One Row Represents | Primary Key (PK) | Approximate Rows (Post-2000) |
| :--- | :--- | :--- | :--- | :--- |
| **`clean_parks.csv`** | **Parks (Venues)** | A unique baseball stadium / ballpark venue. | `park_id` | ~670 venues |
| **`clean_teams.csv`** | **Teams (Franchises)** | An MLB franchise / team code. | `team_id` | ~30+ teams |
| **`clean_games.csv`** | **Games (Daily Logs)** | A single completed MLB game, including attendance, weather, score, and venue. | `game_id` | ~58,000+ games |

## 3. Detailed Data Dictionary

### A. `clean_parks.csv` (Stadiums / Venues)
* **Granularity / Grain**: 1 row = 1 unique stadium.

| Column Name | SQL Type | Description & Domain Rules | Example Values |
| :--- | :--- | :--- | :--- |
| **`park_id`** *(PK)* | `VARCHAR(10)` | Retrosheet unique identifier for the venue. | `'BOS07'`, `'NYC20'`, `'DEN02'` |
| **`park_name`** | `VARCHAR(100)` | Standard/historical stadium name. | `'Fenway Park'`, `'Coors Field'` |
| **`aka`** | `VARCHAR(100)` | Alternative or corporate-sponsored naming rights. | `'Pacific Bell Park'`, `'Enron Field'` |
| **`city`** | `VARCHAR(50)` | Municipality where the ballpark is located. | `'Boston'`, `'Denver'`, `'Toronto'` |
| **`state`** | `VARCHAR(10)` | US state postal code or Canadian province code. | `'MA'`, `'CO'`, `'ON'` |
| **`start_date`** | `DATE / TEXT` | Opening date of the stadium for professional games (`MM/DD/YYYY`). | `'04/20/1912'`, `'04/26/1995'` |
| **`end_date`** | `DATE / TEXT` | Closing date or final game played. Empty/NULL if still active. | `'09/28/2008'`, `NULL` |
| **`league`** | `VARCHAR(10)` | Primary historical league association. | `'AL'`, `'NL'` |
| **`notes`** | `TEXT` | Historical context, demolition info, or special usage notes. | `'Also known as...; demolished in...'` |

### B. `clean_teams.csv` (Franchises)
* **Granularity / Grain**: 1 row = 1 unique MLB franchise identifier.

| Column Name | SQL Type | Description & Domain Rules | Example Values |
| :--- | :--- | :--- | :--- |
| **`team_id`** *(PK)* | `VARCHAR(5)` | Retrosheet 3-letter team code. | `'BOS'`, `'NYA'`, `'LAN'`, `'CHN'` |

> [!NOTE]
> **Retrosheet Two-Team City Codes**:
> Retrosheet distinguishes cities with two teams by league letter:
> * `'NYA'` = New York Yankees (American League) vs. `'NYN'` = New York Mets (National League)
> * `'CHA'` = Chicago White Sox (AL) vs. `'CHN'` = Chicago Cubs (NL)
> * `'LAN'` = Los Angeles Dodgers (NL) vs. `'LAA'` / `'ANA'` = Los Angeles Angels (AL)

### C. `clean_games.csv` (Game Logs & Environmental Conditions)
* **Granularity / Grain**: 1 row = 1 completed MLB baseball game.

| Column Name | SQL Type | Description & Domain Rules | Example Values |
| :--- | :--- | :--- | :--- |
| **`game_id`** *(PK)* | `VARCHAR(20)` | Unique Retrosheet Game ID: `{home_team}{YYYYMMDD}{game_num}`. `game_num = 0` for regular games; `1` or `2` for doubleheaders. | `'BOS200410010'`, `'COL201905150'` |
| **`game_date`** | `DATE` | The calendar date of the game formatted in ISO standard `YYYY-MM-DD`. | `'2004-10-01'`, `'2019-05-15'` |
| **`season`** | `SMALLINT` | Four-digit championship season year. Key partitioning column for rolling multi-year views. | `2004`, `2019`, `2023` |
| **`day_of_week`** | `VARCHAR(15)` | Calendar day name. Highly impactful feature for attendance modeling (Friday–Sunday surges). | `'Monday'`, `'Friday'`, `'Saturday'` |
| **`park_id`** *(FK)* | `VARCHAR(10)` | References `clean_parks.park_id`. The specific stadium where this game took place. | `'BOS07'`, `'DEN02'` |
| **`home_team_id`** *(FK)* | `VARCHAR(5)` | References `clean_teams.team_id`. The designated home team (bats in bottom of innings). | `'BOS'`, `'COL'` |
| **`vis_team_id`** *(FK)* | `VARCHAR(5)` | References `clean_teams.team_id`. The visiting opponent team (bats in top of innings). | `'NYA'`, `'LAN'` |
| **`attendance`** | `INTEGER` | Paid ticket turnstile attendance. Target variable for ticket pricing and dynamic demand models. | `35245`, `48123`, `12400` |
| **`daynight`** | `VARCHAR(10)` | Game start time classification: `'day'` or `'night'`. | `'day'`, `'night'` |
| **`temp`** | `SMALLINT` | Game-time ambient temperature in degrees Fahrenheit (°F). Retrosheet `0` sentinels have been converted to `NULL`. | `72`, `55`, `94`, `NULL` |
| **`sky`** | `VARCHAR(20)` | Overhead sky conditions. Cleaned from `'unknown'` to `NULL`. | `'sunny'`, `'cloudy'`, `'overcast'`, `'dome'`, `'night'` |
| **`precip`** | `VARCHAR(20)` | Precipitation during the game. Cleaned from `'unknown'` to `NULL`. | `'none'`, `'rain'`, `'drizzle'`, `'snow'` |
| **`wind_dir`** | `VARCHAR(20)` | Wind direction relative to home plate. Affects trajectory and ball flight. | `'tocf'` (to center field), `'fromcf'` (from center), `'ltor'` (left to right), `'rtol'` (right to left) |
| **`wind_speed`** | `SMALLINT` | Wind speed in miles per hour (mph). Retrosheet `-1` sentinels converted to `NULL`. | `8`, `15`, `0`, `NULL` |
| **`field_cond`** | `VARCHAR(20)` | Ground moisture / playing surface condition. | `'dry'`, `'wet'`, `'damp'` |
| **`home_runs`** | `SMALLINT` | Total score / runs scored by the **home team**. | `5`, `2`, `11` |
| **`vis_runs`** | `SMALLINT` | Total score / runs scored by the **visiting team**. | `3`, `4`, `0` |
| **`total_runs`** | `SMALLINT` | Total combined game scoring (`vis_runs + home_runs`). Primary variable for calculating stadium Run Park Factors. | `8`, `6`, `11` |
| **`gametype`** | `VARCHAR(20)` | Schedule classification. | `'regular'`, `'postseason'` |

> [!IMPORTANT]
> **Note on "Home Runs"**:
> * In this dataset, `home_runs` represents the **runs scored by the home team** (the score), and `vis_runs` represents **runs scored by the visitor**.
> * Together, `total_runs` allows calculating the **Run Park Factor** (e.g., Coors Field `DEN02` inflating runs vs. Oracle Park `SFO11` deflating runs).

## 4. How to Apply this Data to Your Project Concepts

### 1. Dynamic Park Factor View (Rolling 3-Season Average)
A standard Run Park Factor (PF) compares the average total runs scored per game in a specific home park against the runs scored when those same teams play on the road:
$$\text{PF}_{\text{raw}} = \frac{\text{Runs per game at Venue}}{\text{Runs per game on Road}}$$

In SQL, you can aggregate `total_runs` grouped by `park_id` and `season`, and then use a window function:
```sql
AVG(annual_park_factor) OVER (
    PARTITION BY park_id 
    ORDER BY season 
    ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
) AS rolling_3yr_park_factor
```

### 2. Foreign Key Referential Integrity & Normalization
* `clean_games.park_id` strictly references `clean_parks.park_id`.
* The cleaning script verifies that **zero orphan games** exist, meaning `ALTER TABLE games ADD CONSTRAINT fk_park FOREIGN KEY (park_id) REFERENCES parks(park_id);` will succeed with 100% integrity.
* Stadium details (e.g., `city`, `state`, `park_name`) are stored strictly once in `clean_parks.csv`, satisfying Third Normal Form (3NF).

### 3. Database Evaluation (`EXPLAIN ANALYZE`)
* **Test Case**: Querying games across multiple decades under specific environmental constraints:
  ```sql
  EXPLAIN ANALYZE
  SELECT p.park_name, g.season, AVG(g.attendance), AVG(g.total_runs)
  FROM games g
  JOIN parks p ON g.park_id = p.park_id
  WHERE g.temp >= 85 
    AND g.sky = 'sunny' 
    AND g.day_of_week IN ('Saturday', 'Sunday')
  GROUP BY p.park_name, g.season;
  ```
* You can run `EXPLAIN ANALYZE` before creating an index (Sequential Scan across 58,000+ rows) and after adding composite indexes (e.g., `CREATE INDEX idx_games_weather ON games(temp, sky, day_of_week)` or `CREATE INDEX idx_games_park ON games(park_id)` to show Bitmap Heap Scans and reduced buffer execution costs).
